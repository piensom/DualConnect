# Dual Connect - Team Roles & Responsibilities

## Project Team Structure

This document outlines the roles, responsibilities, and collaboration structure for the Dual Connect MVP development project. The team consists of 5-7 vocational students working collaboratively over 6 project blocks (30-36 weeks).

---

## Team Composition

### Team Size: 5-7 Members
**Time Commitment**: 2 hours per week per person
**Total Project Duration**: 30-36 weeks (6 blocks of 5-6 weeks each)
**Meeting Schedule**: Weekly team meetings (60 minutes) + individual work time

## Collaboration Model

### Weekly Workflow

**Monday**: Individual work on assigned tasks
**Wednesday**: Brief check-in via chat/email (15 min)
**Friday**: Team meeting (60 min)
- Progress updates
- Blocker discussion
- Next week planning
- Knowledge sharing

### Communication Channels

- **Primary**: Weekly in-person/video meetings
- **Async**: Slack/Discord channel or WhatsApp group
- **Documentation**: Shared Google Drive or GitHub
- **Code**: GitHub repository

## Cross-Functional Collaboration

### Key Collaboration Points:

| Roles | Collaboration Need | Touchpoints |
|-------|-------------------|-------------|
| UX Designer ↔ Developer | Handoff wireframes, clarify design intent | Weekly during Blocks C-D |
| Database Designer ↔ Developer | Data integration, JSON structure | Weekly during Block D |
| Content ↔ UX Designer | Content length, tone, placement | Weekly during Blocks B-C |
| Project Lead ↔ All | Status updates, blocker resolution | Weekly throughout |
| Networking ↔ Content | Stakeholder input, real-world data | Bi-weekly during Blocks A-B |
| Documentation ↔ All | Gather deliverables, progress notes | Ongoing throughout |

## Block-by-Block Role Focus

### Block A: Kickoff & Research (Weeks 1-6)
**Lead Roles**: Project Lead, Content/Research, Networking
- Define scope and requirements
- Conduct competitive analysis
- Begin stakeholder outreach

### Block B: Concept & Data Model (Weeks 7-12)
**Lead Roles**: Database Designer, Content/Research
- Design database schema
- Structure content taxonomy
- Create ER diagrams

### Block C: UX Prototype (Weeks 13-18)
**Lead Roles**: UX Designer, Developer (planning)
- Create wireframes
- Design user flows
- Prepare development environment

### Block D: Data Integration (Weeks 19-24)
**Lead Roles**: Developer, Database Designer
- Build HTML/CSS pages
- Integrate sample data
- Implement search/filter

### Block E: MVP Testing (Weeks 25-30)
**Lead Roles**: All (collaborative testing), Networking (user feedback)
- Usability testing
- Bug fixes and refinement
- External user feedback

### Block F: Finalization (Weeks 31-36)
**Lead Roles**: Documentation, Project Lead
- Final report writing
- Presentation preparation
- Lessons learned documentation

## Decision-Making Process

### Consensus-Based Decisions:
- Major feature additions/removals
- Technology choices
- Design direction
- Final deliverable scope

### Role-Based Decisions:
- Individual implementation details
- Tool selection within domain
- Day-to-day prioritization

### Escalation Process:
1. Discuss in weekly meeting
2. If no consensus: Project Lead mediates
3. If still blocked: Consult instructor/advisor

---

## Conflict Resolution

### Principles:
- **Respect**: All opinions are valued
- **Evidence**: Base decisions on user needs and project goals
- **Flexibility**: Be willing to compromise
- **Communication**: Address issues early and openly

### Process:
1. Direct discussion between involved parties
2. Bring to team meeting if unresolved
3. Project Lead facilitates resolution
4. Instructor consultation if needed

---

## Handoff Between Teams (If Applicable)

If teams change between blocks:

### Handoff Requirements:
- **Documentation**: All work must be thoroughly documented
- **Demo**: Live demonstration of current state
- **Q&A Session**: 30-minute handoff meeting
- **Contact**: Outgoing team available for 2 weeks for questions

### Handoff Deliverables:
- Current codebase (GitHub link)
- Documentation (design docs, data schemas)
- Known issues list
- Recommended next steps

## Team Meeting Agenda Template

**Duration**: 60 minutes

1. **Check-in** (5 min): How is everyone doing?
2. **Progress Updates** (20 min): What did each person accomplish this week?
3. **Blockers & Challenges** (15 min): What's blocking progress?
4. **Decisions Needed** (10 min): What requires team input?
5. **Next Week Planning** (10 min): What will each person work on?

## Final Notes

### Flexibility:
- Roles can be combined if team is smaller (5 people instead of 7)
- Team members can support each other across roles
- Adjust time allocations based on individual availability

### Growth Mindset:
- This is a learning project – mistakes are expected and valuable
- Support each other's learning
- Celebrate small wins along the way

### Focus on User Value:
- Always ask: "Does this help international families?"
- Prioritize features that deliver real value
- Stay focused on the MVP scope
